# Exchange contract v1 — PROPOSED, NOT APPROVED

Requires a **constitution Article I amendment**: protocol metadata is needed for authorship, replay control and polls; existing five-field rule cannot implement FR-8/FR-11. `vote-log.schema.json` defines the only cross-node event object; `additionalProperties=false` rejects item text. Draft does not authorize implementation.

## Identity, canonical bytes, signature

Five keypairs are generated locally before launch. Owner manually pins four other Ed25519 public keys (`author_id = SHA-256(raw 32-byte public key).hexdigest()`) in each node's config. No transitive trust or discovery. Serialize the signed object **without** `signature` as UTF-8 JSON: keys sorted lexicographically, no whitespace (`separators=(',', ':')`), `ensure_ascii=True`, integers only (no JSON floats). Sign the resulting bytes with Ed25519; encode 64-byte signature as unpadded base64url. `event_id = SHA-256(canonical_bytes || raw_signature)`. Receive side validates schema and size, reconstructs those bytes, verifies signature using the pinned key matching `author_id`, then persists. JSON duplicate keys are rejected during parsing; do not silently accept last-wins. This canonicalization is specific to the bounded ASCII event shape, not an arbitrary JSON canonicalization standard.

`seq` is monotonically increasing **per author across all event kinds**, allocated and recorded in one local DB transaction before sending. Replay same `(author_id,seq,event_id)` is a no-op. Same `(author_id,seq)` with a different event ID is equivocation: quarantine both variants, exclude them from aggregate, flag the UI. Delivery may be out of order; the receiver stores gaps and advances a contiguous watermark only when missing events arrive. A remote clock does not order votes: latest valid vote for an item is highest `seq` at the evaluation cutoff. `issued_ms` is display/audit metadata, not authority. A per-author sequence is sufficient for an author-owned append-only log; there is no shared mutable object that requires a vector clock.

## Delivery

- Each node binds HTTP to **127.0.0.1** on a configured distinct port; reject non-loopback binds. Endpoint `POST /v1/events` accepts a JSON array of up to 100 signed events, total <= 64 KiB. Return per-event statuses (`accepted`, `duplicate`, `unknown_item`, `rejected`, `equivocation`) with IDs; no title/url/body in responses. Retry on transport failure with bounded delay; receiver idempotence, not exactly-once transport, provides correctness. A missing peer never blocks local ingest or UI.
- `POST /v1/events` does not carry an event envelope that could smuggle arbitrary text. Invalid/oversized batches fail closed; quarantine metadata is local and bounded. Restrict ingress rate per pinned author and log only event ID/cause. Do not expose a public network interface. Signed events prove pinned-key authorship, **not** truth of their vote or protection against a compromised host.
- Poll invitation: `kind=poll_invite`, `item_id`, `poll_id` (random 128-bit lowercase hex), `author_id`, `seq`, `issued_ms`, `signature`. A vote reply includes the same `poll_id`; an ordinary vote omits it. Poll ID is correlation metadata, not a consensus artifact. Unknown item => `unknown_item`, never fetch from the peer. Duplicate poll invites are idempotent. Aggregate only verified votes with matching poll ID and item ID; abstentions count as responses but no positive/negative preference.
- Broadcast only to manually pinned, enabled peers. A revoked peer's events are retained for audit but receive zero rank weight. Revocation is unilateral local state; it does not require consensus or deletion from the peer's machine.

## Privacy and abuse boundaries

An item ID is a truncated hash of a URL; a recipient can hash a guessed URL and match it. "No plaintext content in transport" is true; "private browsing history from peers" is **false**. A peer can also flood legitimate signed events: per-author sequence, quotas and weight caps bound processing and influence but cannot stop a trusted peer from lying. The live feed request and optional local-model download are distinct egress paths; eval runs offline. Acceptance test inspects every serialized request/response for text from fixture items and unknown schema fields, plus replay/equivocation/rate/size cases.
